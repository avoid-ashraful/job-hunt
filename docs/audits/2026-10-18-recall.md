## Addressed False Drops (Already Merged in Commit `51ff50b`)

The 13 false drops in the following categories have already been resolved in commit `51ff50b`:

1. **`agency.for_our_client` (7 false drops recovered):**
   - *Fix:* Greenhouse ATS entity-escaped HTML (`&lt;p&gt;`) is now unescaped prior to plain-text stripping in `scanner/sources/ats.py`. Additionally, the regex in `scanner/rules.py` was narrowed from matching loose phrases like "for our customers" to specifically require explicit hiring agency formulations (`\bon behalf of\s+(?:our|a|one of our)\s+clients?\b` or `\b(?:hiring|recruiting|seeking|looking)\b[^.;\n]{0,100}\bfor\s+(?:our|a|one of our)\s+clients?\b`).
   - *Jobs recovered:* Canonical (jobs 3143, 3144, 3145, 3146, 3147), Sourcegraph (3155), Seeq (3250).

2. **`employment type` (2 false drops recovered):**
   - *Fix:* `scanner/filters.py` now maps Recruitee's `full_time_permanent` to `full_time` and `freelance` to `contract`.
   - *Jobs recovered:* Tiugo Technologies / CKSource (job 168), INDG / Grip (job 88).

3. **`region locked (rule)` (2 false drops recovered):**
   - *Fix:* In `scanner/rules.py`, location place matches adjacent to advisory wording ("preferably", "ideally") or US pay-transparency disclosures ("salary range", "compensation varies") are demoted to `weak_lock` (routing them to LLM screening instead of hard dropping).
   - *Jobs recovered:* GitLab (job 3256: Senior CX Platform Engineer, Remote), Finstock, Inc. (job 3291: Software Engineer - Fintech & AI Platform).

4. **`older than` (2 false drops recovered):**
   - *Fix:* In `scanner/filters.py`, posts older than `max_age` originating from monitored ATS watchlist boards are flagged for live verification (`needs_live`) rather than unconditionally dropped.
   - *Jobs recovered:* Railway (job 104: Senior Full-Stack Engineer - Product Global, job 106: Senior Product Engineer, Scalability Global).

## Remaining False-Drop Patterns & Proposed Solutions

### Pattern 1: Role family omission of Machine Learning & AI Infrastructure roles
- **Issue:** `role_families.applied_ai` in `config.yml` requires titles to match `applied ai`, `\b(ai|llm|gen(erative)?\s?ai|agentic( ai)?)\s+(software\s+)?(engineer|developer)\b`, or `\bai (platform|application|product|systems?) engineer\b`. Titles such as `Machine Learning Engineer`, `Senior ML Engineer`, `Applied ML Engineer`, or `AI Infrastructure Engineer` do not match `applied_ai` or `generic` (which requires the title to begin strictly with senior/staff/lead/principal). As a result, senior Python-based AI/ML engineering roles get dropped under `title not in target role families`.
- **False drops identified:** HFT Architecture (*Machine Learning Engineer*, USD 180k-240k, Python), Kimchi / Cast AI (*Senior ML Engineer*, Python / vLLM / SGLang; *Senior Applied ML Engineer*, Python model router).
- **Proposed change:** Update `role_families.applied_ai` regexes in `config.yml` (and `config.example.yml`) to include:
  ```yaml
  applied_ai:
    - 'applied (ai|ml)'
    - '\b(machine learning|ml)\s+(software\s+)?(engineer|developer)\b'
    - '\b(ai|llm|gen(erative)?\s?ai|agentic( ai)?)\s+(software\s+)?(engineer|developer)\b'
    - '\bai\s*/\s*ml\s+(software\s+)?(engineer|developer)\b'
    - '\bai (platform|application|product|systems?|infrastructure) engineer\b'
  ```

### Pattern 2: Stack filter fails on `Python3`
- **Issue:** In `config.yml`, `python_patterns` contains `'\bpython\b'`. In Python regex, `\bpython\b` does not match `Python3` because `3` is an ASCII word character (`\w`), preventing a word boundary `\b` between `n` and `3`. If a job description exclusively specifies `Python3` in its requirements, the job will fail the Python check and get dropped under `no Python`.
- **Proposed change:** Update `python_patterns` in `config.yml` (and `config.example.yml`):
  ```yaml
  python_patterns: ['\bpython3?\b', '\bdjango\b', '\bfastapi\b', '\bflask\b']
  ```

### Pattern 3: Upstream `posting_language` metadata overrides English content
- **Issue:** In `scanner/rules.py`, `RoleRules.evaluate()` inspects `job.posting_language`. If the source aggregator incorrectly flags the posting as non-English (e.g., `fr`), and the text does not contain explicit "English required" phrases (because the job description is already written entirely in fluent English), the job is dropped immediately with `language.<lang>`.
- **Proposed change:** In `RoleRules.evaluate()`, do not drop purely based on `job.posting_language != "en"` unless a lightweight text inspection confirms the body actually contains non-English words or fails an English word check.

### Pattern 4: Broad single-keyword title exclusion drops multi-role posts
- **Issue:** Hacker News "Who is hiring?" and aggregator listings frequently combine multiple open roles in a single line (e.g. `Close | Backend Engineers, Sr. Software Engineer (Marketing) | REMOTE`). If any segment matches an excluded keyword (e.g. `Marketing`, `Junior`, `Customer`), the entire listing is dropped under `title excluded`, missing valid senior backend positions.
- **Proposed change:** For job titles containing separators (`/`, `|`, `,`, `·`), evaluate role matching and title exclusions per segment so an eligible target role is preserved even if an adjacent distinct opening has an excluded word.
